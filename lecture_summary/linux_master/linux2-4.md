# 일반운영관리

## 사용자 관리
<br>

### 루트계정
- 시스템의 모든 권한을 가진 수퍼유저
- 운영체제 관리에 필요한 모든 작업을 할수 있는 관리자 권한
- UID 0: 시스템은 UID 0 인 계정을 root 로 인식 (이름이 달라도)
- 슈퍼유저 : 모든 파일, 디렉토리, 프로세스, 설정등에 완전한 접근 및 조작 가능
- 시스템 설정, 사용자 관리, 소프트웨어 설치 등 핵심적인 작업 모두 허용
- 파일 시스템의 최상위 (/) 에서 이름을 따옴
- 잘못사용하면 시스템에 심각한 손상
- 일반적으로는 root 로 로그인하지 않고 su, sudo 를 사용해 root로 변환하여 사용
- root 비밀번호는 시스템 설치시부터 지정, 관리자 이외에는 절대 공유 X
- 시스템 보안 유지를 위해 root 계정의 직접 접근을 제한하고 로그 관리 등 추가적인 보호조치 필요
- su - 입력 후 비밀번호를 통해 root 환경으로 전환
- sudo 지정된 사용자에게 일시적으로 root 권한으로 명령 실행 가능 
    - /etc/sudoers 파일에 허용된 사용자만 가능

#### 대표작업
- /etc, /bin, /usr, /root 등 중요한 시스템 디렉토리 파일 수정/삭제
- 새로운 사용자 계정 생성, 삭제, 비밀번호 변경, 그룹 관리 등
- 네트워크 설정, 방화벽 설정, 서비스 (데몬) 시작/중지/재시작, 시스템 전반의 보안설정
- 시스템 전체에 영향을 미치는 패키지 설치 및 제거 (apt, yum, rpm 등)
- 장치 드라이버 및 커널 업데이트
- 권한 변경 (chown, chmod)
- 시스템 백업, 복구, 마운트, 언마운트
- 시스템 프로세스, 종료, 시스템 재푸팅, 셧다운 등

### 시스템 계정
- UID 1~999 
- 서비스(데몬)나 시스템 내 서비스 실행용
- bin, daemon, lp, sys, mail, www-data, adm, sync 등
- 로그인 금지된 상태로 만들어지며 암호 없이도 계정이 활성화될수 있음
- 각 계정별로 역할이 제한. 최소한의 권한만 부여됨
- 홈디렉토리, 로그인 쉘 등도 데몬 실행 목적에 맞게 설정됨
- /etc/passwd, /eetc/shadow 를 통해 계정 정보 확인 가능

#### 대표작업
- 서비스 및 데몬 실행
- 자원 및 권한 분리
- 로그인 불가능한 상태로 운영
- 파일 및 디렉터리 소유자 역할

### 사용자계정
- 일반 사용자 계정 UID 1000 부터 할당

- 주요 시스템 파일
    - /etc/passwd (사용자 계정 정보)
    - /etc/shadow (암호화된 비밀번호 정보)
    - /etc/group, /etc/gshadow (그룹정보 및 보안 설정)
    - /etc/skel (사용자 기본 환경설정 복사용 디렉토리)
    - /etc/login.defs (사용자, 그룹의 기본 범위 및 정책 확인)

- 그룹 계정 관리
    - 사용자 권한과 자원 접근을 효율적으로 통제
    - 그룹 생성, 수정, 삭제, 멤버 관리 등 

- 관련 명령어
    - users : 현재 로그인 되어있는 모든 사용자 출력

    - who : users +  터미널 종류, 로그인 시간등 기본정보 포함

    - whoami : 현재 로그인한 사용자 사용자명 출력

    - w : 현재 로그인한 사용자가 어떤 시스템에서 로그인했는지 어떤 프로세스를 실행하고 있는지 출력

    - logname : 현재 로그인한 사용자의 로그인 출력

    - id : 지정한 사용자의 사용자 정보, 그룹정보 출력. 현재 사용자 정보 출력

    -  groups : 특정 사용자, 현재 로그인한 사용자가 속한 그룹 표시

    - lslogins : wtmp, btmp 로그를 바탕으로 시스템 전체 사용자 출력


## 파일 시스템 관리

#### 링크파일 종류
- 심볼릭 링크
    - 윈도우의 바로가기처럼 원본 파일의 경로를 기록하여 링크 파일이 원본 파일을 참조
    - 파일의 inode (실제 데이터 위치) 와 별개로 독립된 파일로 생성
    - 원본파일이 삭제/이동되면 심볼릭 링크는 broken link
    - 디렉터리나 다른 파일 시스템 간에도 링크 가능
    - ln -s [원본파일경로] [링크파일경로]

- 하드링크
    - 동일한 파일 시스템 내에서만 가능
    - 원본 파일과 동일한 inode
    - 파일을 상제해도 하드링크는 동일 데이터를 계속 참조
    - 모든 링크가 삭제되어야 실제 데이터 삭제
    - 디렉터리에는 사용 불가
    - ln [원본파일경로] [링크파일경로]

#### 디렉토리 관리
- pwd : 절대경로
- cd 이동
- mkdir : 디렉토리 생성 (-p 상위 없으면 같이 생성)
- rmdir : 비어있는 디렉터리 삭제
- ls : 목록 출력
- cp : 복사
- rm : 디렉토리와 그 안의 내용 삭제
- mv : 이동 , 이름변경
