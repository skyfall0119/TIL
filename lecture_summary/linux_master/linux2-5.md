# 일반운영관리2

## 프로세스 관리
<br>

### ps 명령어 (process status)
- 현재 실행중인 프로세스의 상태와 리스트 확인
- 시스템 내 모든 프로세스 혹은 특정 조건의 프로세스 조회
- 윈도우의 작업관리자 같이 프로세스 현황을 cli 에서 확인. 
- 모니터링에 활용

##### ps 주요 옵션
- ps : 현재 터미널 세션의 프로세스만 표시.
- ps e또는 p6-A 전체 시스템의 모든 프로세스 표시.
- ps-f: 프로세스의 상세 정보(UID, PID, PPID, 시작 시간, 명령줄 등) 표시.
- ps -ef : 시스템의 전체 프로세스를 상세 정보 포맷으로 출력. 대부분의 작업에 사용.
- ps aux : BSD 스타일 옵션. 모든 프로세스를 사용자·상태 중심으로 표시.
- ps -u <사용자>: 특정 사용자가 실행한 프로세스만 조회.
- ps x : 터미널과 연결되지 않은 백그라운드 데몬 프로세스도 함께 표시.
- ps -p <PID>: 지정한 PID의 정보만 표시.
- ps -o ... : 원하는 컬럼만 선택 출력(예: PID, COMMAND 등).
- 옵션은 쉼표 없이 붙여서도 사용 가능(예: ps -ef).

##### ps 상태코드

- R: Running: 실행 중 또는 실행 가능한 상태 (CPU 점유 혹은 대기큐)
- S: Sleeping: 대기 상태 (인터럽트 가능), I/O 요청 등으로 기다림
- D: Uninterruptible Sleep: 인터럽트 불가능한 대기상태, 주로 디스크』O대기 중
- T: Stopped: 정지 상태 (Ctrl+Z, SIGSTOP 등으로 일시 중지됨)
- Z: Zombie: 좀비 프로세스, 종료됐으나 부모가 상태 수거하지 않은 자식
- X: Dead: 프로세스가 비정상적으로 종료된 상태 (드물게 나타남)
- I: Idle(커널쓰레드만): 커널 쓰레드가 유휴상태, 사용자 프로세스엔 거의 없음
- t: Traced/Debug: 디버거에 의해 멈춰진 상태

### pstree
- 현재 실행 중인 프로세스들의 부모-자식 관계를 토리(tree) 구조로 한눈에 시각적으로 보여주는 명령어.
- ps 명령어처럼 실행 중인 모든 프로세스를 나열하는 것이 아니라, 계층관계(부모-자식 관계)를 트리 형태로 보여줍니다.
- 시스템 관리자가 "init"이나 "systemd"로부터 파생된 각 프로세스가 어떤 관계로 생성·실행되는지 직관적으로 확인할 수 있습니다.
- 프로세스 관리, 트러블슈팅, 특정 프로세스의 하위 그룹 조사 등에 활용됩니다.

##### pstree 주요옵션
- -a : 명령행 인자 및 옵션까지 표시.
- -c : 동일한 하위트리 구조도 반복 출력.
- -h : 현재 프로세스와 부모 프로세스를 화이라이身.
- -n : PID 기준으로 성렬
- -p : 각 프로세스의 PID함께표시.
- -U : UID(실행 사용자)도 함께 표시.
- pstree [PID] 또는 pstree [USER]: 지정한 프로세스 또는 사용자를 기준
으로 트리 출력

### top
- top 명령어는 실시간으로 시스템의 프로세스 상태를 모니터링하고, 다양한 관리 기능을 제공
- 실행 중인 모든 프로세스의 리스트, CPU/메모리 사용량, 각 프로세스의 상태 등을 3초 간격 기본 갱신으로 실시간 출력합니다.
- 각 행의 주요 정보에는 PID, USER, PR(우선순위), NI(nice값),
VIRT/RES/SHR(메모리), S(상태), %CPU, %MEM, TIME+(누적 CPU시
간), COMMAND 등이 있습니다

##### 주요옵션
top 실행 후 키 입력으로 다양한 관리 작업을 수행
- k 특정 프로세스 종료(프로세스 PID 입력, signal 번호 입력 - 기본 15,
강제 9).
- U : 특정 사용자 프로세스만필터
- r : 프로세스의 NICE 값 변경(우선순위 조정).
- f : 표시 항목 설정(열 커스터마이즈).
- i : 유휴(IDLE)/좀비(ZOMBIE) 프로세스 숨김.
- H : 쓰레드 기준 리스트 출력.
- q : top 종료.
- 프로세스 리스트 정렬
    - Shift+p : CPU 사용률 내림차순
    - Shift+m : 메모리 사용률 내림차순
    - Shift+n : PID 오름차순
    - Shift+t : 실행된 시간 순
- 기타
    - top -b : 배치 모드(스크립트/로그 저장용)
    - top -n <횟수>: 지정 횟수만 반복 후 종료
    - top -p <PID>: 특정 PID(프로세스)만 모니터링


## 프로세스 종료

### kill
- kill 명령어는 실행 중인 프로세스에 종료 또는 제어 신후를 보내는 데 사용
- kill [옵션]RID 옵션을 통해 다양한 신호를 보낼 수 있으며, 신호를 지정하지 않으면 기본적으로 SIGTERM(15)을 보냅니다. 이 신호는 정상적으로 프로세스 종료를 요청합니다.
    - kill -15 <PID> # 정상 종료
    - kill -9 <PID># 강제 종료 
    
- kill -9 PID : SIGKILL(9) 신호로 강제 종료. 프로세스가 응답하지 않을 때 사용하며,
데이터 손실 가능성이 있습니다.
- kill -1 PID : SIGHUP(1) 신호로 재시작이나 설정 재로드를 유도합니다.
- kill -l : 시스템에서 사용 가능한 모든 시그널 목록을 출력합니다.
- 프로세스 그룹 및 사용자별 종료
    - kill -9 -PID : 해당 프로세스 그룹 전체에 신호를 전송합니다.
    - kill -u 사용자명 : 특정 사용자의 모든 프로세스에 신호 전송


### killall
killall 명령어는 프로세스의 이름을 기준으로 한 번에 여러 동일한 이
름의 프로세스를 종료할 수 있습니다.

- killall [옵션] 프로세스명
- 예를 들어 동일한 python3 프로세스가 여러 개 실행될 경우 -> killall python3
- 특정 사용자 소유의 프로세스 종료 -> killall -u user python3

## 프로세스 전환

### jobs
jobs 명령어는 현재 셸 세션에서 실행 중이거나 일시 중지된 작업(프로
세스)의 목록과 상태를 표시하는 작업 제어 명령어이다.

- jobs는 백그라운드나 Ctrl+Z로 일시 중지한 작업을 포함해 셸이 관리
하는 전체 작업을 번호별로 보여줍니다.
- 각 작업에 대해 작업 번호, 프로세스 ID, 상태(Running, Stopped, Done
등), 실행령령을 출력합니다.
- 작업 번호로 fg, bg, kill 같은 명령어에서 %번호 형식으로 대상 지정이
가능합니다.

##### 주요 옵션
- jobs -l: 각 작업의 프로세스ID(PID)도 함께 출력.
- jobs -p: 각 작업의 PID만 출력.
- jobs -n: 마지막으로 상태가 변경된 작업만 출력.
- jobs -r: 실행 중인(Running) 작업만 출력.
- jobs -s: 일시 중지된(Stoppd) 작업만 출력.

---

### fg
fg 명령어는 백그라운드나 일시 중지된 작업을 포그라운드(현재 셸 입
력 상태)로 전환하는 자업제어 명령어이다.

- fg는 "foreground"의 약자로, 백그라운드에서 실행 중이거나 Ctrl+Z로
일시 중지된 작업을 다시 셸의 포어그라운드에서 활성화합니다.
- fg 또는 fg %[번호]형식으로 사용하며, %[번호]는 jobs 명령어로 확인
한 작업 번호입니다.
- 번호를 생략하면 가장 최근에 중지 또는 백그라운드로 전환된 작업
을 포어그라운드로 가져옵니다.

---

### bg
bg 명령어는 현재 터미널 세션에서 일시 중지된 작업(프로세스)을 백그
라운드에서 계속 실행하도록 재개하는 리눅스 잡 컨트롤 명령어이다.

- bg는 일반적으로 Ctrl+Z로 일시 중지된 작업을 다시 백그라운드에서
실행(재개)할 때 사용합니다.
- bg [잡 번호]

- bg 명령은 반드시 일시 중지된 작업에만 적용 가능하며, 이미 실행 중
인 프로세스에는 사용할 수 없습니다.
- 여러 작업이 있을 경우 작업 번호를 함께 지정해 원하는 작업만 백그라
운드로 재개해야 합니다.
- 백그라운드로 이동하면 해당 작업이 터미널 입력을 점유하지 않으므
로, 다른 명령이나 작업을 병행할 수 있습니다


## 프로세스 우선순위
### nice
nice 명령어는 새로운 프로세스를 실행할 때 해당 프로세스의 실행 우선
순위(niceness)를 직접 지정하여 시스템 리소스(특히 CPU 사용량)를 조
절할 수 있는 명령어이다.

- nice 값이란, 프로세스의 "친절도"를 의미하며, 수치가 높을수록 그
프로세스가 CPU를 더 양보한다는 뜻입니다.
- 우선순위 조정 범위는 -20(가장 높은 우선순위)에서 19(가장 낮은 우
선순위)까지입니다.
- 기본적으로 일반 사용자는 nice 값을 높일(우선순위 낮춤) 수만 있으
며, 낮출(우선순위 높임) 경우 root 권한이 필요합니다
- 기본 구문:
    - nice -n [nice값][명령어]
    - nice -n 10 python3 myscript.py
    - nice 값 10으로 python3 실행 →CPU 점유 우선순위가 낮음.
    - 옵션을 명시하지 않으면 기본적으로 10이 적용되어 실행됩니다.
    - 시스템 기본값(부모의 nice값)은 o입니다.

---

### renice
renice 명령어는 이미 실행 중인 프로세스의 우선순위(nice 값)를 동적으
로 변경하는 데 사용한다.

- nice 명령어는 새로운 프로세스 실행 시 우선순위를 정하는 데 사용
되지만, renice는 "실행 중인" 프로세스의 우선순위를 즉시 변경할 수
있습니다.
- 우선순위(niceness)값은 -20(가장 높은 우선순위)에서 19(가장 낮은
우선순위)까지 지정할 수 있습니다. 더 낮은 값은 더 높은 CPU 우선
권한을 줍니다.
- 일반 사용자는 자신의 프로세스에 대해 nice 값을 높이는(우선순위
춤) 건만 허용되며 우선순위 높임(-간)은 root 권한이 필요합니다.

- renice [nice값] -p [PID] 
    - sudo renice -5 -p 5678
    - PID 5678의 nice 값을 -5로 변경(더 높은 우선순위).
- 특정 사용자(user)의 모든 프로세스 우선순위 변경: sudo renice 15 -U 사용자명
- 특정 그룹(group)의 모든 프로세스 우선순위 변경: sudo renice 10 -g 그룹ID

---

### nohup
nohup 명령어는 터미널 세션이 종료되거나 로그아웃되어도 프로세스를 계속 실행할 수 있
도록 하는 명령어이다.

- nohup은 "no hangup"의 약자이며, 터미널 연결이 끊길 때 전송되는 SIGHUP(세션 종료) 신호를 무시하도록프로세스를 실행합니다.
- 서버 작업이나 오래 걸리는 배치 작업을 SSH나 터미널상에서 실행할 때, 중단 없이 계속
실행해야 할 때 자주 쓰입니다.

- 프로그램 또는 스크립트 앞에 nohup을 붙이고 실행:
    - nohup[실행할 명령어] &
    - (& 를 프로그램 실행시에 명령어 맨 끝에 붙여주면 해당 프로그램이 백그라운드로 실행됨)

## 프로세스 검색
### pgrep
grep 명령어는 실행 중인 프로세스 중에서 이름이나 조건이 일치하는 프로세스의 PID(프로세스ID)를 빠르게 찾는 데 사용되는 명령어이다.

- 구문:
    - pgrep [옵션] <패턴>
    - 예: pgrep ssh
    - 실행 중인 ssh 관련 프로세스의 PID를 모두 출력.
- 정규식과 부분 매칭을 지원하며, 프로세스 이름뿐 아니라 다양한 속성
조건을 옵션으로 줄 수 있습니다.

- 예시
    - 사용자 root의 ssh 프로세스 이름과 PID 확인: pgrep -I -u root ssh
    - python이라는 전체 명령줄(스크립트명포함)에 해당되는 프로세스 PID
    찾기: pgrep -f python
    - 가장 최근 실행된 nginx 프로세스 찾기: pgrep -n nginx
    - PID 목록을 쉼표로 구분해서 출력: pgrep -d, bash

##### 주요 옵션
- | : PID와 함께 프로세스 이름 표시
- a : PID와 전체 명령줄 표시
- U <사용자> : 지정 사용자가 실행한 프로세스만 검색
- f : 전체 명령줄로 패턴 검색(명령어 인자까지 포함)
- X : 프로세스 이름과 정확히 일치하는 것만 검색
- n : 일치하는 프로세스 중 가장 최근(pid가 큼) 것만 출력
- o : 일치하는 프로세스 중 가장 오래된(pid가 작음) 것만 출력
- c : 일치하는 프로세스의 개수 출력
- d<구분자> : 여러 PID 출력 시 구분자(기본: 줄바꿈) 지정
- V : 지정 조건과 일치하지 않는 프로세스만 출력
- P <PPID> : 특정 부모 PID 하위 프로세스만 검색
- t <tty> : 지정 터미널에서 실행된 프로세스만 검색

## 프로세스 관련 파일
### Iproc 디렉터리
- 리눅스의/proc 디렉터리는 커널의 정보를 실시간으로 제공하는 가상 파일 시
스템(procfs)으로, 프로세스 및 시스템 상태, 하드웨어, 네트워크 등 다양한 정
보를 파일 형태로 보여줍니다.

- /proc 내의 파일과 디렉터리는 실제 하드디스크에 저장되지 않고, 메모리
에서 동적으로 생성·관리됩니다.
- 커널 내부 데이터구조(메모리, CPU, 네트워크, 부팅정보 등)에 대한 텍스
트 기반 인터페이스를 제공하며, 시스템 부하 없이 실시간 정보를 조회할
수 있습니다.
- 관리자나 개발자가 시스템 상태 모니터링, 프로세스 추적, 성능 측정, 커널

## 설치 관리
### 패키지를 통한 소프트웨어 설치 개요
- Rocky Linux
- Rocky Linux 8에서 패키지 관리자를 통한 소프트웨어 설치는 주로 dnf 명
령어를 사용해 손쉽게 패키지(프로그램)를 설치·삭제· 업데이트하는 방식이다.
- Rocky Linux 8의 기본 패키지 관리자는 dnf(Dandified Yum)이며, yum 명령어도 사용은 가능하지만 내부적으로는 dnf가 호출됩니다.
- 패키지(프로그램)는 저장소(Repository)에 등록되어 있고, dnf는 인터넷을 통해 공식 저장소로부터 소프트웨어.라이브러리 패키지를 다운받아 설치합니다.
